# Classes that exist in both src/mobile and src/wear with the same fully-qualified
# name. The watch copy is a stub or a diverged fork of the phone one, and nothing
# checks they agree — change the phone class and the watch build still compiles
# while the watch feature silently does nothing.
#
# This list may only shrink. NoDuplicateFqnTest fails if a new pair appears, and
# also if an entry here is no longer a duplicate (a stale line means a pair was
# fixed but not removed from the list, so the guard would stop noticing it).
#
# Removed so far: tk.glucodata.receivers.AlarmLaunchReceiver (T5.1).
#   tk.glucodata.Stats, tk.glucodata.Watch (category P): their watch stubs had no
#   caller anywhere in src/main or src/wear, so they were deleted.
#   tk.glucodata.GlucoseAlarms (category S): the alert path, so it was characterised before
#   being changed (GlucoseAlarmsAsymmetryTests pins the phone/watch differences). The shape
#   was a held reference, not a call: shared code held SuperGattCallback.glucosealarms as
#   the concrete class and both construction sites were in src/main. No interface was added,
#   because the contract already exists in src/main as SuperGlucoseAlarms; the field is typed
#   to that and the instance comes from GlucoseAlarmsAccess, which registers a factory per
#   flavour. The classes are MobileGlucoseAlarms and WearGlucoseAlarms.
#   tk.glucodata.settings.SetColors (category S): both sides are real -- 144 lines on the
#   phone, 96 on the watch, and the watch's adjusts the light bars and opens its own colour
#   dialog -- so both are renamed (MobileSetColors, WearSetColors) and both register behind
#   SetColorsScreenAccess. The contract is the one method the settings screen calls.
#   Worth writing down how this duplicate hid from the compiler: Settings is in the same
#   package, and show was package-private on both sides, so shared code called a phone class
#   by a name the watch happened to share as well.
#   tk.glucodata.settings.LabelsClass (category P): the shared Settings.java now opens
#   it through the LegacyScreens registry, so its watch stub was deleted.
